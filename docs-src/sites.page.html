This extension ships the data, the API, and an admin screen for managing them. A site that wants its own screens (a dashboard, a stock page, a storefront) builds them itself, and can reuse the same browser modules the admin uses.

The browser SDK

The API client is at /inventory/sdk.js. Every call resolves to [error, result], where error is { code, msg } or null.

import { getItems, getFields, adjustStock } from '/inventory/sdk.js';

const [error, data] = await getItems({ q: 'paint', limit: 20 });
// data.items, data.total, data.linked (item links), data.media (photos)

await adjustStock(itemId, { delta: -5, reason: 'sold', note: 'Order 1042' });

Whoever is calling needs the matching permission, or the public_read setting must be on. Stock counts only come back for people who manage stock. See who sees stock counts.

Forms and dialogs

The item form builds itself from the field list, so custom fields, item links and photo uploads work without any code of your own.

import { openItemDialog, openAdjustDialog } from '/inventory/components/ItemDialog.js';

openItemDialog({ item, fields, onSaved: item => reload() });                    // edit an item
openItemDialog({ fields, defaults: { category: 'Paint' }, onSaved });           // a new item, with a category filled in
openItemDialog({ fields, askQuantity: false, defaults: { quantity: 1 }, onSaved });
openAdjustDialog({ item, onSaved: item => reload() });                          // add or remove stock

fields is the full list from getFields(). The form shows the default fields plus those of the item's category, and swaps them as the category changes. If you want your own layout, fieldTemplate and readField (from ItemFields.js) render and read a single field's input, and displayValue gives a plain-text version that is safe to put in a table cell.

Adding and editing items

Adding and editing are pages, not dialogs, because a dialog closes with a stray tap and takes everything entered with it. A site gets the same pages the admin uses:

import { mountNewItemPage, mountEditItemPage, safeNext } from '/inventory/components/NewItemPage.js';
import { showFlash } from '/inventory/components/flash.js';

mountNewItemPage({ $container, fields, defaults: { category: 'Paint' }, askQuantity: false, next: '/category?name=Paint' });
mountEditItemPage({ $container, item, fields, context: { linked, media, ownId: item.id }, next: '/items/' + item.id });
showFlash();   // on the page it goes back to: shows "Added ..." or "Saved ..." once

The new-item page has Create item, Create and add another and Cancel. The edit page has Save and Cancel. While anything entered has not been saved, leaving the page triggers the browser's own "changes may not be saved" prompt, and Cancel asks before discarding. window.hasUnsavedInventoryWork() tells anything else that wants to move the page whether to hold back.

next must be a path on the same site. safeNext(value, fallback) refuses anything else, which stops a link being used to send someone to another site.

The barcode scanner

The scanner behind the item form's Scan button is a module you can use too:

import { scanBarcode } from '/inventory/components/BarcodeScanner.js';

const code = await scanBarcode();   // the code's text, or null if cancelled

For a scanner that stays on screen and keeps going, such as a "scan page", use startScanner with your own <video>:

import { startScanner } from '/inventory/components/BarcodeScanner.js';

const scanner = await startScanner({ video: $video, onCode: code => lookUp(code) });
scanner.setPaused(true);   // ignore codes while a dialog is open
scanner.stop();            // release the camera
  • onCode fires once each time a code comes into view. The same code is not reported again until it has left the frame for a moment, so holding a bottle still gives one scan, and scanning the next bottle of the same paint gives another.
  • It rejects if the camera can't be started. cameraProblem() and explainCameraError() turn that into a sentence you can show.
  • The camera is switched off as soon as a code is read or the dialog is closed.
  • openItemDialog({ defaults: { sku } }) opens the new-item form with a SKU already filled in, which is how a site can offer "no item has this barcode, create it?".

Tags in your own forms

ItemFields.js exports tagsValue(tags), suggestTags and readTags($tags) for use with kempo-ui's tag box: <k-tags .value=${tagsValue(tags)} .getSuggestions=${suggestTags}>. readTags includes text typed but not yet added, so saving never loses a tag.
