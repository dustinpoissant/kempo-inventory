Who can read the inventory

Reading the inventory needs the items:read permission. Turn on the public_read setting (off by default) and anyone can read it, signed in or not, so it can be shared as a catalogue. Public reading covers items, categories and fields, and their photos. Writing always needs the matching permission.

Who sees stock counts

Stock counts are only for people who manage stock. A caller without stock:adjust or items:update gets items without a quantity, and no stock history. That covers a signed-out visitor, someone signed in with only items:read, and public reading. People who manage stock get everything.

Photos and files

Photos and files are optional. Three other extensions can take part. Inventory never loads any of them up front, each is detected when it is needed, and with none installed nothing else changes: the "Photos / files" field kind is simply not offered.

ExtensionRole
kempo-mediaA media library: a kempo-files file plus kind, dimensions and alt text, with thumbnails from kempo-thumbs. It requires the other two, so installing it brings all three
kempo-filesA file library: files live outside public/, and every download is permission-checked unless the file is marked public
kempo-thumbsMakes thumbnails for kempo-files, including frames from video and audio

Add a field of the kind "Photos / files" and every item gets an upload area. When an item has more than one photo, the first is its primary photo, the one shown on cards and lists. Each other photo has a Make primary button.

New uploads go to kempo-media when it is installed (it is kempo-files with thumbnails, so one upload gives a stored file and its thumbnail), and to kempo-files directly on a site that has only that. There is no setting to choose: the old media_provider setting was retired, and the update removes it.

A stored value records where its file lives (a bare id is a kempo-media asset, files:<id> a kempo-files file), so values written earlier, or by a site with only kempo-files, keep working on the same item as newer ones.

  • If a library is disabled later, items keep their stored ids and everything else keeps working. Files from that library show as missing, and only adding a file from it is refused.
  • Deleting a file from its library leaves the id on the item, shown as a missing file.
  • Permissions: the inventory groups do not grant media permissions, since those belong to the optional extensions. Uploading needs media:upload (kempo-media) or files:upload (kempo-files). With kempo-files, viewing a photo needs files:download too, so give read-only users a group that has it.

Who can see a photo

kempo-files only serves a file to people with its files:download permission, which someone who can merely read the inventory does not have, so their photos would be broken images. The public_photos setting (on by default) uploads photos as public, whether they go to kempo-media or kempo-files: viewable by anyone who has the link (the ids are unguessable), which includes every inventory reader. Turn it off to keep photos behind files:download, and then give your readers that permission. Changing the setting only affects new uploads.

Photo shape and size

A "Photos / files" field can force how photos are saved. When you create or edit one, set either or both of:

  • Force photo shape: an aspect ratio such as 1:1, 4:3 or 16:9. Each photo added opens in kempo-ui's image cropper, locked to that shape, so only that shape can be saved. Skip leaves a photo out.
  • Max size (px): photos are kept within this many pixels on a side, scaled down and never up. With only a max size and no shape, photos are scaled down with no cropper.

Leave both empty and photos are uploaded as they are. The stored file is the cropped one, so the shape holds everywhere it is shown. Anything the browser cannot edit (GIF, SVG, HEIC, video) is uploaded untouched. A category's picture is always cropped to the category_image_ratio setting.

How images are shown

Two settings under Admin > Settings, category_image_ratio and item_image_ratio, set the aspect ratio images are shown at, written width:height (4:3 by default). Images are cropped to fit the shape and never stretched, and the originals are not changed, so changing the setting reshapes every image at once. The admin's pickers use them, and GET /inventory/api/fields returns them as imageRatios so a site can do the same.
